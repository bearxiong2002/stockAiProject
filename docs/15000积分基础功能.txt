# Datahubco 客户 API 调用手册

> 目标：客户按统一格式一次调用成功，避免因接口名、日期、代码、分页或字段写法错误而失败。
> 版本：2026-08-27；接口参数以 Tushare 官方文档和上游返回为最终准则。

## 1. 先记住这 8 条

1. 当前客户入口是 `GET /app-api/openapi/v1/tushare/{api}`；接口名使用清单中的小写下划线写法。
2. 客户密钥只放在请求头 `X-API-Key`，不要放在 URL、日志或代码仓库里。
3. `fields` 是返回列选择，不是业务筛选参数；多个字段用英文逗号分隔。
4. 日期统一使用 `YYYYMMDD`，财报期通常使用季度末 `YYYYMMDD`；电视剧备案使用 `YYYYMM`，神奇九转可能使用时间戳。
5. `start_date` 和 `end_date` 必须成对；不要同时发送 `trade_date` 与区间参数。
6. `limit`、`offset` 只能是非负整数；使用 `offset` 时必须同时给 `limit`。建议每页不超过 5,000 行。
7. `code=0` 且 `items=[]` 表示查询成功但没有匹配数据，不是服务器故障。
8. 本网关不增加客户侧限流；但 Tushare 上游的积分、权限和频率规则仍然生效。

## 2. 地址与鉴权

当前公开域名为 `datahubco.com`，示例中的 `BASE_URL` 请替换为实际入口：

```text
BASE_URL=http://datahubco.com
API_KEY=你的客户密钥
```

当前服务器仍以 HTTP 80 提供服务，HTTPS 尚未配置。生产环境不要在不可信网络中明文传输密钥；待证书上线后，把 `BASE_URL` 改为 `https://datahubco.com`。

### cURL 通用模板

```bash
curl --get "${BASE_URL}/app-api/openapi/v1/tushare/daily" \
  -H "X-API-Key: ${API_KEY}" \
  -H "X-Request-Id: client-demo-0001" \
  --data-urlencode "ts_code=000001.SZ" \
  --data-urlencode "trade_date=20260825" \
  --data-urlencode "fields=ts_code,trade_date,open,close"
```

### Python requests 通用模板

```python
import requests

url = "http://datahubco.com/app-api/openapi/v1/tushare/daily"
headers = {"X-API-Key": "YOUR_CUSTOMER_KEY", "X-Request-Id": "client-demo-0001"}
params = {"ts_code": "000001.SZ", "trade_date": "20260825", "fields": "ts_code,trade_date,open,close"}
response = requests.get(url, headers=headers, params=params, timeout=30)
response.raise_for_status()
payload = response.json()
if payload.get("code") != 0:
    raise RuntimeError(payload.get("msg", "unknown API error"))
rows = payload["data"]["items"]
```

### 返回格式

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "fields": ["ts_code", "trade_date", "close"],
    "items": [["000001.SZ", "20260825", 12.34]]
  }
}
```

`items` 是按 `fields` 顺序排列的数组；不要按固定列号猜字段，先读取 `data.fields` 再映射。

## 3. 参数规则速查

| 参数 | 写法 | 常见用途 | 易错点 |
|---|---|---|---|
| `ts_code` | `000001.SZ`、`600000.SH`、`00001.HK` | 股票/指数/基金/债券/合约代码 | 后缀必须正确；多个代码仅在官方说明支持时用逗号分隔 |
| `trade_date` | `20260825` | 单日行情或单日统计 | 不是 `2026-08-25` |
| `start_date` + `end_date` | `20250101` / `20251231` | 时间区间 | 两个必须同时出现，且开始不晚于结束 |
| `period` | `20251231` | 财报期/季度 | 不能写 `2025Q4` |
| `date` | `20260825` | 利率、票房等非交易表 | 电视剧接口使用 `YYYYMM` |
| `fields` | `ts_code,trade_date,close` | 选返回列 | 不要重复、不要写 `trade-date`；未知字段会被上游拒绝 |
| `limit` / `offset` | `100` / `0` | 分页 | 只能是非负整数；`offset` 必须配 `limit` |

### 缓存与本地数据提示

- 返回头 `X-Data-Source: sqlite`、`X-Cache: LOCAL` 表示本地 SQLite；`X-Data-Source: redis`、`X-Cache: HIT` 表示 Redis 热命中；`upstream/MISS` 表示回源。
- 参数顺序不会影响缓存键，但 `fields` 的字段顺序会影响键；客户应固定字段顺序。
- 实时/分钟类接口不要期待历史缓存；本地数据只对已证明完整的请求形状生效。

## 5. 逐接口调用说明

### 股票

#### 1. `daily` - 日线行情

**用途**：全部历史，交易日15-17点更新。
**积分提示**：清单标注最低积分 `120起`；本代理能路由不等于客户账号已开通上游权限。
**官方参数文档**：https://tushare.pro/document/2?doc_id=27
**调用选择**：可用单日或区间查询：`trade_date`；或 `start_date`+`end_date`。区间查询建议同时给 `ts_code`；不要把 `trade_date` 与区间参数混用。

**推荐请求**：

`GET {BASE_URL}/app-api/openapi/v1/tushare/daily?ts_code=000001.SZ&trade_date=20260825&fields=ts_code,trade_date,open,high,low,close`

**输入参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ts_code` | `str` | 否 | 股票代码（支持多个股票同时提取，逗号分隔） |
| `trade_date` | `str` | 否 | 交易日期（YYYYMMDD） |
| `start_date` | `str` | 否 | 开始日期(YYYYMMDD) |
| `end_date` | `str` | 否 | 结束日期(YYYYMMDD) |

**常用返回字段**：`ts_code`, `trade_date`, `open`, `high`, `low`, `close`。
**本服务器行为**：已验证本地 SQLite 快路径（符合完整性条件的请求）；重复请求可命中 Redis。未满足本地条件的形状会自动回源。

---

#### 2. `weekly` - 周线行情

**用途**：全部历史，每周五更新。
**积分提示**：清单标注最低积分 `2000`；本代理能路由不等于客户账号已开通上游权限。
**官方参数文档**：https://tushare.pro/document/2?doc_id=144
**调用选择**：`ts_code` 与 `trade_date` 二选一；区间查询使用成对的 `start_date`、`end_date`。

**推荐请求**：

`GET {BASE_URL}/app-api/openapi/v1/tushare/weekly?ts_code=000001.SZ&start_date=20250101&end_date=20251231&fields=ts_code,trade_date,close,open,high,low`

**输入参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ts_code` | `str` | 否 | TS代码 （ts_code,trade_date两个参数任选一） |
| `trade_date` | `str` | 否 | 交易日期 （每周最后一个交易日期，YYYYMMDD格式） |
| `start_date` | `str` | 否 | 开始日期 |
| `end_date` | `str` | 否 | 结束日期 |

**常用返回字段**：`ts_code`, `trade_date`, `close`, `open`, `high`, `low`。
**本服务器行为**：默认走上游账号池；符合缓存策略的成功响应可能命中 Redis，但不承诺本地覆盖。

#### 4. `pro_bar` - 复权行情

**用途**：分钟/指数/基金/期货除外。
**积分提示**：清单标注最低积分 `2000`；本代理能路由不等于客户账号已开通上游权限。
**官方参数文档**：https://tushare.pro/document/2?doc_id=146
**调用选择**：官方接口要求 `ts_code`、`asset`、`freq`；但官方说明 HTTP 方式不能调取，本网关不要调用。

**推荐请求**：

`本网关不提供该接口的 HTTP 调用；不要复制下面的 URL 到客户程序。`

**输入参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ts_code` | `str` | 是 | 证券代码 |
| `start_date` | `str` | 否 | 开始日期 (格式：YYYYMMDD) |
| `end_date` | `str` | 否 | 结束日期 (格式：YYYYMMDD) |
| `asset` | `str` | 是 | 资产类别：E股票 I沪深指数 FT期货 FD基金 O期权，默认E |
| `adj` | `str` | 否 | 复权类型(只针对股票)：None未复权 qfq前复权 hfq后复权 , 默认None |
| `freq` | `str` | 是 | 数据频度 ：1MIN表示1分钟（1/5/15/30/60分钟） D日线 ，默认D |
| `ma` | `list` | 否 | 均线，支持任意周期的均价和均量，输入任意合理int数值 |

**常用返回字段**：以响应中的 `data.fields` 为准；建议先不传 `fields`。。
**特别注意**：官方文档明确说明该接口通过 SDK 动态计算复权，HTTP 方式无法调取。本客户网关是 HTTP GET；请改用 `stk_factor_pro`（静态技术因子）或直接使用官方 Python SDK。
**本服务器行为**：不支持通过本 HTTP 网关调用；请使用官方 SDK 或改用可通过 HTTP 的静态接口。

官方 SDK 形态（直连 Tushare，不经过本客户网关）：

```python
pro.pro_bar(ts_code="000001.SZ", start_date="20250101", end_date="20251231", asset="E", freq="D", adj="qfq")
```

#### 5. `daily_basic` - 每日指标

**用途**：PE/PB/市值/换手等。
**积分提示**：清单标注最低积分 `2000起`；本代理能路由不等于客户账号已开通上游权限。
**官方参数文档**：https://tushare.pro/document/2?doc_id=32
**调用选择**：`ts_code` 或 `trade_date` 至少提供一个；按单股票区间查询时同时给 `ts_code`、`start_date`、`end_date`。

**推荐请求**：

`GET {BASE_URL}/app-api/openapi/v1/tushare/daily_basic?ts_code=000001.SZ&trade_date=20260825&fields=ts_code,trade_date,close,turnover_rate,turnover_rate_f,volume_ratio`

**输入参数**：

| 参数 | 类型 | 必填 | 说明 |

## 6. 错误信息与处理方式

| HTTP | `code`/现象 | 含义 | 客户处理 |
|---:|---|---|---|
| 400 | `invalid api name`、`fields must be a string` | URL、字段或请求格式错误 | 检查接口名、字段名和 JSON/查询参数类型 |
| 401 | `missing X-API-Key`、`invalid, disabled or expired token` | 未带客户密钥或密钥无效 | 只使用 `X-API-Key`，确认密钥状态和过期时间 |
| 200 | `code=0`、`items=[]` | 请求成功但没有数据 | 检查代码、日期、交易所和权限，不要当成服务器错误 |
| 502 | `Tushare request failed` | 上游权限、参数、频率或网络失败 | 记录 `X-Request-Id`，先看 `msg`；不要盲目改成另一个接口 |
| 503 | `authentication service temporarily unavailable` | 鉴权后端临时不可用 | 稍后重试并保留请求 ID |

### 最常见的 10 个写错方式

1. 把 `token` 放进 URL；正确做法是请求头 `X-API-Key`。
2. 把 `000001` 当成完整代码；A 股应写 `000001.SZ`，上交所股票应写 `600000.SH`。
3. 日期写成 `2026-08-25`；行情接口通常要求 `20260825`。
4. 只写 `start_date` 不写 `end_date`。
5. 同时写 `trade_date`、`start_date`、`end_date`。
6. 把财报期写成 `2025Q4`；应写 `20251231`。
7. `offset=100` 却不写 `limit`。
8. `fields` 中重复字段、使用连字符或夹带空格。
9. 把指数代码、基金代码、期货合约代码当股票代码使用。
10. 把上游“无权限/频率超限”误认为本网关限流；本项目没有添加客户侧限流。

## 7. 分页示例

```python
def fetch_all(base_url, api_key, api, fixed_params, fields):
    rows = []
    offset = 0
    while True:
        params = {**fixed_params, "limit": 5000, "offset": offset, "fields": fields}
        r = requests.get(f"{base_url}/app-api/openapi/v1/tushare/{api}", headers={"X-API-Key": api_key}, params=params, timeout=30)
        r.raise_for_status()
        body = r.json()
        if body.get("code") != 0:
            raise RuntimeError(body.get("msg"))
        batch = body.get("data", {}).get("items", [])
        rows.extend(batch)
        if len(batch) < 5000:
            break
        offset += 5000
    return rows
```

分页时每一页都要保留相同的业务筛选条件和 `fields`，只递增 `offset`。若上游接口自身限制更小，以返回错误提示为准。

## 9. 重要边界

清单共有 81 行、80 个唯一 API（`index_daily` 重复一次）。目前服务器已用真实数据和 HTTP 请求验收 9 个本地接口族：`daily`、`daily_basic`、`adj_factor`、`index_daily`、`index_dailybasic`、`fund_daily`、`cb_daily`、`stock_basic`、`trade_cal`。其余接口仍以 Tushare 上游权限、参数和频率返回为准；“清单标注可用”不能替代客户账号的实际授权。

本手册中的示例日期用于演示格式，不保证每个日期都有数据；请按交易日历和接口更新时点替换。
